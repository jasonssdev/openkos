# Proposal: A TypeScript Client For The Local API, With Node CI

Tracking issue: #1458. Governing decisions: ADR-0065 (the desktop web view is
TypeScript built with Vite, over a client generated from the OpenAPI snapshot;
Proposed, accepted by this change), ADR-0061 (the local API is a FastAPI adapter
whose OpenAPI schema a client is generated from), ADR-0058 (loopback HTTP with a
per-launch bearer token), ADR-0055 (the Tauri shell), ADR-0063 and ADR-0064 (the
identity-group and unmerge operations whose refusals the client types).

## Intent

The local API (archived as `2026-10-16-local-http-api`) publishes an OpenAPI
schema and commits it as a snapshot, `tests/unit/localapi/openapi.json`. Every
archived stage since has left "the TypeScript client" to this stage: the
local-http-api change measured a one-off generation and deferred the client and
its Node CI; `#1422` made the preview's plan a discriminated union on `kind` so
a generated client could narrow it; the engine-freeze change listed the client
as out of scope. The desktop shell's status page still calls `GET /v1/status`
by hand in untyped JavaScript.

The next stage, the review screen, calls most of the API and must word every
refusal the [wording brief](../../../docs/decision-wording.md) lists. This
change gives it a typed client to stand on, held to the snapshot by CI, and
proves the client end to end by moving the status page onto it.

## Scope

### In scope

- **The client** under `desktop/client/`: types generated by openapi-typescript
  from the snapshot and committed; one typed method per operation over a
  hand-written call with no runtime dependency; the base URL and token taken from the shell's `engine_state`;
  the error envelope mapped to typed errors, with the busy "try again" case and a
  bounded automatic retry for it; plans narrowed on `kind`; the token kept out of
  every error, string and serialisation of the client.
- **The drift check**: the committed types are regenerated in memory and
  compared byte for byte with the snapshot's output; the error codes the client
  names are compared with the engine's error table.
- **The build**: `desktop/` becomes a pnpm package (lockfile committed); Vite
  builds the page from `desktop/ui/` into the ignored `desktop/dist/`, which
  becomes Tauri's `frontendDist`. `desktop/scripts/build-app.sh` builds the page
  before it bundles.
- **Node CI**: a job that installs from the frozen lockfile, typechecks, runs the
  client's unit tests, runs the drift check and builds the page. The shell's two
  existing jobs build the page before they compile.
- **The status page** moved to TypeScript and onto the client.
- Docs: `docs/architecture.md` (the `desktop/` tree), `CONTRIBUTING.md` (the
  page build in the shell's dev loop), CHANGELOG and the roadmap's status line.

### Out of scope

- The review screen and any new screen (the next stage); guided setup; the
  updater; choosing a workspace in the app.
- Any change to the engine, the local API or its snapshot. `API_VERSION` stays 1.
- A client published to npm, or used outside the desktop app.
- Windows and Linux builds of the app.

## Approach

`desktop/package.json` pins Node 24 and pnpm, with TypeScript 5.9,
openapi-typescript 7, Vite and vitest as development dependencies and no runtime
dependency. `desktop/scripts/schema.mjs` generates
`desktop/client/schema.d.ts` from the snapshot (`pnpm generate`) or checks it
(`pnpm check:schema`), using one function for both so they cannot disagree. The
client's calls name a path template and method of the generated `paths` and
take their body and answer types from that operation, so an
API change that alters a field the client or the page uses fails `tsc`.

## Risks And Rollback

- **The shell now needs Node to compile.** Tauri refuses to compile without its
  `frontendDist`, so `cargo test` needs the page built first. Mitigated by one
  documented command and by CI building it in both shell jobs. Rollback: revert
  `frontendDist` to `../ui` and restore the static page; the client package can
  stay.
- **A new supply chain.** Pinned by `pnpm-lock.yaml`, installed with
  `--frozen-lockfile`; development dependencies only, so nothing from npm but
  the bundler's output ships in the page.
- **Drift between the snapshot and the client.** This is what the drift check
  exists for; a change that regenerates the snapshot without the client fails
  the Node job.
- Every slice is a squash-merged PR; reverting one restores the previous state.
