**Learned**:
1. `_stage_filed_answer` called `_slugify`, a CLI-shared utility used at 8 OTHER `main.py` call sites (ingest, tarball extraction, LLM staging) — the application layer cannot import it from `openkos.cli` (layering invariant, AST-enforced by `test_layering.py`). Resolved by promoting `slugify`/`_is_slug_char`/`_SLUG_COLLAPSE_RE` to `bundle/source_titles.py`, mirroring that same file's own documented precedent (`titleize` was promoted there from `_titleize` for the identical reason). `main.py`'s `_slugify` now delegates; all 126 pre-existing `test_slugify.py` approval tests passed unchanged, proving byte-identical behavior. This dependency was NOT named in design.md's D3 "moves" list — a real design gap, resolved by following the codebase's own established pattern rather than duplicating the Unicode-normalization logic (identity-critical, per the function's own docstring).
2. The Slice 2 gate command `uv run pytest --cov=src/openkos/application tests/unit/application -q` initially measured only 48.80% coverage even though `stage_filed_answer`'s exhaustive behavioral scenarios (30+ cases: title cascade, sensitivity high-water-mark, slug collisions, NFC/NFD citation lookups) already existed and passed in `tests/unit/cli/test_query_save.py` via the `_stage_filed_answer` alias — because that file isn't collected by a `tests/unit/application`-scoped invocation. The exhaustive approval-test coverage living at the CLI layer does NOT count toward an application-layer-scoped coverage gate. Fixed by adding a compact, non-duplicative set of ~15 direct tests in `tests/unit/application/test_query_filing.py` that reuse the exact known-good fixtures/expected values already pinned in `test_query_save.py` (never re-derived), reaching 98.09%.
3. `mypy .` (whole-repo) caught a real break my own repo-wide grep had noted but initially deprioritized as "eval script, out of scope": `evals/query_title/run_query_title_probe.py` imported the 4 moved title-cascade functions directly from `openkos.cli.main`, including a `cli_main._QUESTION_SUBJECT_PREFIXES` monkeypatch trick for its `scaffold` measurement arm. CI lints the WHOLE repo including `evals/`, so this needed fixing (repointed to `openkos.application.query`), confirming the "known fact" instruction that a targeted grep is not sufficient — only running the actual gate commands catches every real break.

Verified stderr-order preservation (task 8.1's "byte-identical" requirement) via `git diff -- src/openkos/cli/main.py | grep -E '^[+-]\s*typer\.echo'` returning ZERO lines — proof no `typer.echo` call was added, removed, or reordered anywhere in the diff, stronger evidence than "the tests still pass" alone.
