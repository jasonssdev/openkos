## Requirement-vs-Code Check

Each requirement was read against `desktop/src-tauri/src/` and `desktop/ui/`, not against the task list.

| Requirement | Result |
|-------------|--------|
| The Engine Is Located Before It Is Started | Met. `locator::locate` resolves `OPENKOS_WORKSPACE` against the working directory (else uses it), refuses a non-directory before any spawn, runs `OPENKOS_ENGINE serve --workspace <dir>` or `uv run --project <checkout> openkos serve --workspace <dir>` with the workspace as the working directory. The supervisor turns a locator error into a final `failed` with reason `engine_not_located` and no restart. |
| The Token Goes Over Stdin And The Port Comes From The Ready Line | Met. `Token::generate` is 32 `getrandom` bytes as 64 hex characters, regenerated by every `engine::start`; it is written as the first stdin line and appears nowhere else (`Debug` is redacted). `parse_ready_line` enforces `event`, `127.0.0.1`, port 1..65535, a `/` base path and `api_version` 1, and ignores unknown keys. Every failed start (`exited_before_ready`, `bad_ready_line`, `not_ready`, `cancelled`) kills and reaps the engine's process group. |
| A Crashed Engine Is Restarted Within A Bounded Budget | Met. `RestartPolicy::default` is 3 restarts in 60 s, 0.5 s doubling to a 4 s cap; `RestartBudget::on_failure` forgets failures older than the window and returns `None` once the budget is spent, after which the state is `failed` with the reason and stderr tail. |
| Quitting Stops The Engine And A Killed Shell Leaves None | Met. The engine is spawned with `process_group(0)`; `RunningEngine` holds its stdin until `stop`, which drops it, waits up to `SupervisorConfig::stop_grace` (8 s), then `SIGKILL`s the group and reaps. `RunEvent::Exit` calls `Supervisor::shutdown`. Standard-library pipes are close-on-exec, so no other child holds the write end. |
| The Web View Reads The Engine State And Calls The Local API | Met. `engine_state` returns `EngineState`, serialised with a `state` tag and the fields the requirement lists. `ui/main.js` reads `GET <base_url>/status` once per ready engine (keyed on pid and base URL) with the bearer token, shows folder, sources, concepts and the sum of open decisions, and writes every value with `textContent`. `tauri.conf.json` sets `connect-src ipc: http://ipc.localhost http://127.0.0.1:*`. |

## ADR-0055: What This Stage Realises

ADR-0055 is accepted for its decision that the desktop shell is Tauri 2 and that the shell starts, supervises and stops the engine as a separate process, handing it its token over stdin and killing it on a graceful exit. Parts of the ADR's Decision are realised only by later stages, and nothing in this change claims them:

- **The `externalBin` wrapper and the frozen one-directory engine as a bundle resource** belong to the freeze stage (ADR-0056). This stage runs the development engine through the engine locator, with bundling switched off.
- **The updater signed with a project-owned minisign key** has not started.
- **The parent-PID guard in the engine.** The ADR's Decision says the engine carries a stdin-EOF plus parent-PID guard. The engine has the stdin-EOF lifeline only, and this change did not add the parent-PID poll, because the engine was out of scope and the measurement below needed no poll. The freeze stage should check this again on its frozen launcher, which could hold its own copy of the pipe.

## Deviations From The Design

1. **The engine is spawned with `std::process`, not `tauri-plugin-shell`** (design D3, decided in the plan). The plugin's child handle cannot close stdin, which would turn every stop into a kill. The freeze stage's locator resolves the `externalBin` path and the supervisor runs it the same way.
2. **`Supervisor::shutdown` takes `&self` (S2b).** S2a shipped it as `&mut self`; Tauri's managed state is shared, so S2b made it callable from any thread, joining under the thread lock so a second caller waits for the first stop. A test pins it.
3. **The live test is part of CI, not only a local check.** The design named it; S2b also made CI install the engine with `uv sync --locked` and run it, so a change to the engine's handshake or Origin allowlist fails the `desktop` job.
4. **No `exploration.md`.** The change was planned without a separate exploration artifact.
